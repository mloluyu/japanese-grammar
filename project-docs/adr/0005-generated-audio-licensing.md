# ADR-0005：生成音频的许可与模型分发策略

- 状态：Accepted
- 日期：2026-10-12

## 背景

例句音频已从「待贡献」改为离线批量生成：`scripts/generate-audio.mjs` 用开源 TTS 引擎 piper-plus（0.8.1，MIT）驱动模型 `ayousanz/piper-plus-tsukuyomi-chan`（基座 `ayousanz/piper-plus-base`，CC BY-4.0）合成，产物 mp3 入库至 `docs/public/audio/`。所选模型以「つくよみちゃんコーパス」（CV. 夢前黎）为训练语料，其利用规约允许合成语音作为鑑賞用作品的一部分发布（含商用），但**禁止以「允许他人将合成语音作为素材再利用」的形式公开**，并要求固定格式的署名。

站点内容默认以 CC BY-NC-SA 4.0 发布，该许可向公众授予共享与改编权。若音频被内容许可覆盖，即构成规约禁止的再利用授权——这是本次决策前发现的真实冲突。

## 备选方案

1. 音频随内容许可走 CC BY-NC-SA 4.0：许可统一、表述最简，但向公众授予了二次利用权，违反语料规约，不可行。
2. 换用许可完全宽松（如 CC0）的语音模型：无许可负担；但宽松许可的候选模型经盲听质量不可接受（css10-ja 已淘汰），继续评测新模型成本高且不保证有解。
3. 音频从内容许可范围中剔除，仅限站内收听（鑑賞用），不授权二次利用：与语料规约允许的发布形态一致；NC 限制比语料条款（允许鑑賞用作品商用）更严格，为其子集，二者不矛盾。

## 决策

采用方案 3。站点许可自本决策起分三层：

1. 代码与配置——MIT；
2. 创作内容（语法讲解、例句、练习题）——CC BY-NC-SA 4.0；
3. 例句音频——不在 CC BY-NC-SA 4.0 范围内，仅限站内收听，不授权二次利用，不得标注 CC0。

配套约束：

- 模型文件不随仓库或站点分发：`tools/models/` 被 git 忽略，模型由维护者按《开发与部署指南》§4 从 Hugging Face 下载至本地缓存。
- 若未来需要分发模型本体或其派生物，须先落实语料规约的继承条款（由语料派生的部分继续按该规约处理）。
- 声明落点四处，口径必须一致：`LICENSE.content`（例外段）、`README.md` §许可证、`docs/team/index.md`（三层声明＋开源引用＋模型来源）、页脚 copyright 注记。
- `content/audio-manifest.json` 逐条记录许可快照；`scripts/audio.config.json` 的 `license` 字段为声明源。

## 后果

- 与语料规约合规，且无需放弃质量已验收的模型；语料要求的署名已在声明落点中体现。
- 贡献者仍只需编写例句文本（多音字补 `reading`），音频由管线生成并自动带上正确归属。
- 成本：许可表述在四处维护，修改时须同步；文档一致性问题已列入 TESTING 发布验收清单。
- 音频无法作为可下载素材提供给群友；如需语音素材应引导至语料官方页。

## 复审条件

- 语料利用规约发生变更（以官方页为准）；
- 产品需要向访客提供音频下载或再授权；
- 更换 TTS 模型、引入自录音频或模型分发需求出现时。
