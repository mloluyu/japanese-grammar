# 贡献指南

这个站点的维护欢迎任何人参与。**不需要会编程**——大多数贡献只是改文字，全程可以在浏览器里完成。

::: tip 完全没写过 Markdown？
页面文字用的是 Markdown——一种几分钟能上手的简单排版写法（标题前加 `#`、加粗用两个星号包住）。入门教程见 [GitHub 官方中文指南](https://docs.github.com/zh/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)；

也可以让网页版 AI 帮你把内容整理成需要的格式，做法见[语法条目编写指南](/contribute/writing-guide)里的提示框。
:::

## 从你想做的事出发

- **发现内容有错** → [报一个 Issue](https://github.com/mloluyu/japanese-grammar/issues/new/choose)，选「内容纠错」，把页面、位置和正确写法写清楚即可，不需要自己动手改。
- **想顺手修一两处文字** → 用下面的「网页修改五步」，几分钟就能完成。
- **想写新语法条目、补充例句或出练习题** → 先读对应分册，再按「网页修改五步」提交：
  - [语法条目编写指南](/contribute/writing-guide)——条目结构与开头信息块的填法
  - [练习题编写指南](/contribute/quiz-guide)——难度怎么定、好题的标准
  - [内容审核指南](/contribute/review-guide)——合并前的把关清单，也适合提交前自查
- **会用命令行，想本地预览站点或改功能** → 见仓库根目录 `CONTRIBUTING.md` 的「本地开发」。只想改内容的话，不需要这一步。

## 网页修改五步

以修改某个语法页面为例（站点地址 `/grammar/tara` 对应仓库里的 `docs/grammar/tara.md`）：

1. 在 GitHub 上打开要改的文件，点右上角的铅笔图标进入编辑。
2. 直接修改内容。
3. 改完点上方绿色按钮 **Propose changes**（提议修改）。GitHub 会让你写一句修改说明，并默认勾选「提交到新分支」——保持默认即可。「分支」可以理解为一份草稿副本，合并前不会影响站点。
4. 接着页面会出现绿色按钮 **Create pull request**（创建 PR），点它、再确认一次。PR 就是"请求把草稿并入正式站点"，你的改动会完整展示给审核者。
5. 页面下方会出现几个圆点状的自动检查。等它们全部变绿后，维护者会来审核；如果出现红叉，把点开后的报错文字贴到 PR 评论区即可，不用自己排查。

合并之后站点会自动更新，不需要再做别的。

## 动笔前要知道的四件事

1. **每条语法有唯一 ID**（如 `tara`）。文件名、例句文件、练习题都靠这个 ID 对应——新建条目前先确认 ID 没被占用。
2. **分类和标签尽量复用现有值**。分类只能用站点已定义的分类，标签优先选已有的——索引和筛选页靠它们保持整齐。
3. **例句不写在页面正文里**，而是放在条目同名的数据文件中（照现有条目抄格式即可）。页面上的假名开关和音频播放都依赖它。
4. **「相似表达」一节只写差别说明**。条目之间的跳转链接由系统自动生成，不用手写。

## 侵权投诉

站点内容以群友原创整理为主，但难免出现表述与他人作品雷同或引用不当的情况。发现涉嫌侵权的内容，请通过任一渠道告诉我们：

- [提交侵权检举 Issue](https://github.com/mloluyu/japanese-grammar/issues/new?template=06-copyright.yml)（推荐，处理进度可追踪）；
- 邮件：[awako@mloluyu.uno](mailto:awako@mloluyu.uno)。

请在反馈中写明涉及的页面、涉嫌侵权的具体内容与原作品出处；确认属实后我们会下架相关内容。
