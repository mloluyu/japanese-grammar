# 语言知识编写指南

> 语言知识区收录语法条目之外的参考内容：术语解释、数词等基础知识、跨条目的对比辨析。不需要会编程，写好一个 Markdown 文件即可。

## 1. 什么内容适合放在这里

满足「**讲一个知识，而不是讲一个句型**」的内容都归这里：

- **语法术语解释**：什么是自动词与他动词、什么是音读与训读、什么是活用；
- **基础知识**：数词与量词、敬语体系概览、假名与罗马字对应等；
- **跨条目对比辨析**：一组容易混淆的句型放在一起讲清楚差别（如「と・ば・たら・なら」的边界）。

**边界**：有明确接续方式、能配例句和练习的句型，请写成[语法条目](/contribute/writing-guide)，不要在这里新建；术语性质的解说则写进语言知识区，**不要为它新建语法条目**（否则语法索引会被没有等级的条目打乱）。

## 2. 文件与命名

- 位置：`docs/reference/<slug>.md`，如 `docs/reference/jidoushi-tadoushi.md`。
- `slug` 用小写英文单词加连字符，见名知义，且不与已有文件重名。
- 开头信息块只需要一个标题：

```markdown
---
title: 自动词与他动词
---
```

没有等级、分类、标签——这些是语法条目专属的。正文第一个 `# 标题` 与 `title` 保持一致。

## 3. 推荐结构

本区没有固定格式、**不强制配例句**。例句直接写在正文里即可（不需要数据文件，也没有音频和练习）。可参考现有页面 `docs/reference/jidoushi-tadoushi.md`，它用了这样的骨架：

```markdown
# 自动词与他动词

## 怎么区分
（一两段讲清判断方法）

## 常见的成对自动词·他动词
（Markdown 表格：自动词 / 他动词 / 含义）

## 注意
（容易踩的坑，如「公園を散歩する」这类例外）

## 和语法条目的关系
（链接到相关语法条目，说明在哪一步会用到这个知识）
```

写对比辨析类页面时，把「**什么时候只能用 A、什么时候只能用 B、什么时候都可以**」讲成可操作的标准，比罗列规则更有用。

链接到语法条目直接写站内路径：`[〜たら](/grammar/tara)`。

## 4. 发布步骤

1. 按上面的格式写好文件，放进 `docs/reference/`。
2. **需要维护者代做一步**：在 `docs/.vitepress/config.ts` 的侧边栏里登记这个页面（这一处是配置文件，交给维护者或写在 PR 说明里即可）。
3. 总览页（`/reference/`）的列表**自动更新**，不需要改它。
4. 按「网页修改五步」提交 PR，等自动检查变绿。

## 5. 提交前自查

- [ ] `slug` 未与已有文件重名，且一看文件名就知道讲什么
- [ ] 信息块只有 `title`，没有等级/分类字段
- [ ] 术语类内容没有顺手建成语法条目
- [ ] 站内链接路径正确（`/grammar/<id>`、`/reference/<slug>`）
- [ ] 引用他人表述时注明出处，没有粘贴未经许可的教材内容
